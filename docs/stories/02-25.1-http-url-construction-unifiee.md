# Story 25.1 — Construction d'URL HTTP unifiée : `queryParams` partout + encodage de l'URL finale

**Epic** : 25 — Bugs remontés par les migrations de connecteurs
**Type** : Bug
**Priorité** : Haute (bloque toute migration avec URL paramétrée)
**Ordre d'implémentation** : **02 / 17** — phase A — Fondations
**Prérequis** : aucun
**Débloque** : Story 25.5, Story 26.11

## Contexte

Deux défauts distincts partagent la même cause racine : il n'existe **pas de constructeur d'URL partagé**. Chaque module HTTP reconstruit son endpoint à sa façon, et seul `httpRequest` (output) a une implémentation complète.

### Symptôme 1 — `queryParams` accepté mais ignoré

`queryParams` est déclaré dans `$defs/httpRequestBase` (`internal/config/schema/common-schema.json:189`), donc **hérité par `httpPolling`, `http_call` et `httpRequest`**. La struct partagée le porte également (`internal/moduleconfig/shared.go:16`).

Mais la seule lecture du champ se trouve dans l'output :

- `internal/modules/output/http_request_url.go:20` et `:85` — `h.request.QueryParams`

Aucune occurrence dans `internal/modules/input/http_polling*.go` ni `internal/modules/filter/http_call.go`.

Conséquence : un pipeline qui déclare `queryParams` sur `httpPolling` ou `http_call` **valide sans avertissement** et part en production avec des paramètres silencieusement perdus. C'est le pire mode d'échec possible : ni erreur de validation, ni log.

### Symptôme 2 — Seuls les paramètres sont encodés, pas l'URL finale

Dans `resolveEndpointForRecord` (`internal/modules/output/http_request_url.go:53`) :

1. Le template `{{record.x}}` est rendu par substitution textuelle dans l'endpoint (`renderField`, ligne 56).
2. Les `keys` de type `path` sont encodés (`url.PathEscape`, ligne 70).
3. Les `keys` de type `query` sont encodés (`q.Set` + `q.Encode()`, lignes 86-93).

Une valeur de template contenant un espace, `&`, `#`, `?`, `+` ou un caractère non-ASCII est donc injectée brute dans l'URL. Selon le cas : paramètre tronqué, paramètre fantôme injecté, ou `url.Parse` qui échoue et retombe silencieusement sur l'endpoint non validé (`return endpoint, nil`, ligne 79).

Cas réel de migration : un filtre `?name={{record.customerName}}` avec `customerName = "Dupont & Fils"` produit une requête avec un paramètre `Fils` parasite.

## Comportement attendu

1. `queryParams` est honoré à l'identique sur `httpPolling`, `http_call` et `httpRequest`, y compris avec templates dans les valeurs.
2. Toute valeur injectée dans l'URL — segment de path issu d'un template, valeur de query param, valeur de `keys` — est percent-encodée selon son contexte (`url.PathEscape` pour le path, encodage query pour la query string).
3. La structure de l'URL écrite par l'auteur du pipeline n'est pas altérée : les `?`, `&`, `/` littéraux de l'endpoint restent structurels. Seules les **valeurs interpolées** sont encodées.
4. Un endpoint final non parsable est une **erreur**, pas un warning suivi d'un envoi.

## Approche suggérée

Extraire un constructeur d'URL partagé (`internal/httpclient` ou `internal/moduleconfig`) consommé par les trois modules, qui prend : endpoint brut, contexte de rendu, `queryParams`, `keys`. L'encodage contextuel doit être appliqué **au moment du rendu du template** (comme le fait déjà `template.TargetURL`), pas après coup sur une chaîne déjà concaténée — sinon on ne sait plus distinguer un `&` structurel d'un `&` de donnée.

Vérifier ce que `template.TargetURL` garantit déjà aujourd'hui : si l'échappement URL est en place pour les valeurs, le trou porte peut-être seulement sur certains chemins d'appel.

## Critères d'acceptation

- `AC1` — Un pipeline `httpPolling` avec `queryParams: {status: open}` émet une requête vers `...?status=open`.
- `AC2` — Idem pour `http_call`.
- `AC3` — Les valeurs de `queryParams` acceptent les templates (`{{record.id}}`, `{{ state.lastTimestamp }}` cf. Story 25.5) et sont encodées.
- `AC4` — `queryParams` déclaré à la fois dans l'endpoint (`?a=1`) et dans `queryParams` : la précédence est documentée et testée (comportement actuel de l'output : `q.Set` écrase).
- `AC5` — Un template dont la valeur contient `& # ? + espace` ainsi qu'un caractère UTF-8 produit une URL correctement encodée, vérifiée sur les 3 modules.
- `AC6` — Un endpoint final invalide après rendu retourne une erreur de module (respectant `onError`), sans requête émise.
- `AC7` — Tests de non-régression : les endpoints sans template ni `queryParams` sont émis **inchangés** (pas de round-trip `url.Parse`/`String` qui normalise l'URL).
- `AC8` — `go test ./...` et `golangci-lint run ./...` passent.
