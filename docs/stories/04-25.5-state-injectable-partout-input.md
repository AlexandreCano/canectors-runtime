### AC6 — table de correspondance (rupture assumée)

| Input | Avant | Après |
|---|---|---|
| `database` | `state.lastRunTimestamp` | `state.lastTimestamp` |
| `database` | `state.lastRunId` | `state.lastId` |
| `soapPolling` | `record.state.lastID` | `state.lastId` |
| `soapPolling` | `record.state.lastTimestamp` | `state.lastTimestamp` |
| `soapPolling` | `record.pagination.*` | `pagination.*` |
| `soapPolling` | `state` absent au premier run | `state` toujours publié |
| `httpPolling` | *(aucune variable)* | `state.lastTimestamp`, `state.lastId` |

Même **racine** partout, pas seulement les mêmes feuilles : `state` et
`pagination` sont des variables de premier niveau y compris côté SOAP, où elles
étaient des champs d'un record synthétique qui n'a jamais existé côté source
(cohérent avec la racine unique de 25.4). `soapclient` les transporte via
`XMLTemplateVars` ; `soapRequest` et `soap_call`, qui rendent contre un vrai
record, ne passent rien et sont inchangés.

Noms alignés sur les tags JSON de `persistence.State` — un seul vocabulaire du fichier d'état jusqu'au gabarit. Source unique : `persistence.RenderState`.

### Décisions actées

- **Raccourcis `queryParam` conservés** (point 4) : une ligne couvre le cas courant, le gabarit couvre le reste. Les deux cohabitent, la valeur d'état gagne sur un `queryParams` de même nom.
- **Premier run** : `lastTimestamp` vaut l'epoch — une comparaison naïve signifie donc « tout depuis le début », ce qui est le comportement voulu. `lastId` est **absent** et non vide : aucune valeur ne signifie « pas encore de curseur » dans tous les schémas, et une chaîne vide ne peut pas être rattrapée par `default()`, alors qu'une variable absente le peut.

### Bug découvert en cours de route

`{{ state.lastTimestamp }}` dans un filtre OData produisait un **400** — pas à cause de l'état, mais des espaces littéraux de la grammaire OData (`LastModifiedDate gt `). `url.Parse` les accepte, les conserve dans `RawQuery`, et `RequestURI()` les envoie bruts : le serveur découpe la ligne de requête dessus. Aucune erreur avant l'envoi, et l'échec se lit comme un problème de syntaxe de filtre.

Corrigé par `httpclient.NormalizeURL`, appliqué sur les trois modules HTTP. Un espace brut n'étant jamais valide dans une URI, l'encoder est sans ambiguïté ; un `%20` déjà écrit n'est pas ré-encodé, et la forme de la query est préservée (AC7 de 25.1).

### Correctifs issus de la revue de code

| Sujet | Correctif |
|---|---|
| Query ré-encodée en ajoutant un paramètre | `MergeQueryParams` conserve verbatim les paramètres déjà présents et n'ajoute que les nouveaux, triés. Avant, `$filter` repartait en `%24filter`, les espaces en `+`, et les paramètres réordonnés — décodable par un serveur conforme, mais ce n'est pas la requête décrite par le pipeline. Même correction sur `buildEndpointWithState`, les clés `query` de `http_call` et celles de `httpRequest`, qui refaisaient le même round-trip. |
| Espaces encodés en `+` | Les valeurs ajoutées sont encodées avec `%20` (`EscapeQueryComponent`), comme le fait déjà le moteur de gabarits : `+` ne vaut espace que sous les règles form-encoded, que la source n'est pas tenue de suivre. |
| Racine SOAP différente | `state` et `pagination` deviennent des variables de premier niveau dans le corps SOAP (cf. table AC6). |
| État publié malgré une persistance désactivée | `RenderState` prend la config : un fichier d'état écrit avant un `timestamp.enabled: false` n'injecte plus un watermark que le pipeline ne suit plus. |
| Nom d'état inexistant rendu en silence | `ValidateStateReferences` rejette au démarrage tout `state.<inconnu>` dans l'endpoint, les headers, `queryParams` et le body — un `{{ state.lastTimestmp }}` produisait `LastModifiedDate gt ` et un 400 côté source. |
| `state.*` sans `statePersistence` | Warn explicite au chargement du module : les variables rendent toujours, mais rien n'est jamais écrit et chaque run repart de l'epoch. |
| Échappement du body figé en JSON | `bodyTarget()` choisit l'échappement d'après le `Content-Type` déclaré (JSON, XML, form-urlencoded, sinon aucun). Sans `Content-Type`, JSON comme avant. |

### Correctifs issus de la seconde revue

| Sujet | Correctif |
|---|---|
| Query ré-encodée par la pagination | `buildPaginatedURLMultiFrom` faisait encore le round-trip `url.Values` sur un endpoint déjà façonné par `Fetch` : dès qu'un bloc `pagination` était présent, `$filter` repartait en `%24filter` et ses `%20` en `+`. Passé à `MergeQueryParams` — c'était le chemin le plus proche de l'exemple 28. |
| Query ré-encodée par l'auth api-key | `apiKeyHandler.ApplyAuth` en `location: query` s'exécute en dernier, sur l'URL finale, et la ré-encodait entièrement pour ajouter la clé. Même correction. |
| Query ré-encodée côté SOAP | `soaputil.BuildEndpointWithKeys` était le quatrième site du round-trip, non converti avec les trois autres. |
| `$` échappé dans les noms de paramètres | `EscapeQueryComponent` produisait `%24top` pour un `queryParams` nommé `$top`, à côté du `$filter` littéral gardé de l'endpoint — deux orthographes dans une même URL. `$` est un sub-delim autorisé verbatim dans une query (RFC 3986), il n'est plus échappé. Les tests assertent désormais sur `RawQuery` : `Query().Get("$top")` décode `%24top` et ne pouvait pas voir la différence. |
| Warn de persistance trop grossier | `timestamp.enabled` et `id.enabled` sont deux interrupteurs distincts : un pipeline qui ne persiste que l'ID mais filtre sur `state.lastTimestamp` repartait de l'epoch à chaque run sans avertissement, puisque `IsEnabled()` était vrai. Le warn est désormais émis par variable lue et non persistée. |
| Expressions multi-lignes non validées | `templateExpr` sans `(?s)` : un `{{ … }}` réparti sur plusieurs lignes dans un `body` échappait à `ValidateStateReferences`, typo comprise. Symétriquement, `{{ x \| default('state.unknown') }}` était rejeté à tort — les littéraux entre quotes sont désormais neutralisés avant la recherche de références. |
| `If-Modified-Since` dans l'exemple 28 | RFC 9110 §8.8.3 exige un HTTP-date et impose d'ignorer une valeur malformée : le RFC3339 rendu là n'aurait rien fait. L'exemple et la doc utilisent `X-Since`, avec la note expliquant pourquoi. |

Tests ajoutés : forme combinée endpoint templé + `queryParams` (celle de l'exemple 28), raccourci `queryParam` sur un endpoint déjà porteur d'une query, variable d'état inconnue rejetée, `record.state.x` non confondu avec une référence d'état, échappement du body par `Content-Type`, `state` racine et premier run côté SOAP, gating de `RenderState` par la config, préservation de forme et déterminisme de `MergeQueryParams`.

## Contexte

L'état persistant n'est aujourd'hui consommable qu'à travers des points d'injection **fermés**, un par module :

| Input | Point d'injection de l'état | Preuve |
|---|---|---|
| `httpPolling` | uniquement `statePersistence.timestamp.queryParam` et `statePersistence.id.queryParam` | `common-schema.json:611`, `:631` |
| `soapPolling` | l'état est exposé au gabarit du corps SOAP sous `state["lastTimestamp"]` | `internal/modules/input/soap_polling.go:307-309` |
| `database` | expressions de paramètres `state.lastRunTimestamp` / `state.lastRunId` | `internal/modules/input/database.go:229-234`, `input-schema.json:134` |

Trois modules, trois conventions, et pour `httpPolling` la seule sortie possible est **un query param dont le nom est fixé par la config** — impossible de mettre le watermark dans :

- un segment de path (`/orders/since/{{ state.lastTimestamp }}`)
- un header (`If-Modified-Since`)
- le corps d'une requête POST de recherche (cas très fréquent : API de search paginée en POST)
- une valeur de `queryParams` libre (cf. Story 25.1)
- un filtre construit (`$filter=LastModifiedDate gt {{ state.lastTimestamp }}` — OData, Salesforce SOQL, etc.)

Par ailleurs `buildRequest` (`internal/modules/input/http_polling_request.go:22`) reçoit l'endpoint déjà résolu et **n'effectue aucun rendu de gabarit** : il n'existe même pas de point d'accroche pour un template dans l'endpoint d'un input HTTP.

C'est ce trou qui a bloqué le plus de migrations : la plupart des API sources filtrent l'incrémental autrement que par un query param simple.

## Comportement attendu

1. Un **contexte de rendu unique** `state.*` disponible dans tous les champs paramétrables de tous les inputs, avec les mêmes noms de variables partout.
2. Champs concernés au minimum : `endpoint`, `headers.*`, `queryParams.*`, `body`, `bodyTemplateFile`, et l'équivalent SOAP.
3. Convention de nommage unifiée entre les 3 inputs (aujourd'hui `state.lastTimestamp` côté SOAP vs `state.lastRunTimestamp` côté database) — choisir un nom canonique et aligner, en cassant si nécessaire.
4. Les points d'injection historiques (`timestamp.queryParam`, `id.queryParam`) restent valables comme raccourci, ou sont retirés au profit du gabarit — **décision à trancher** ; recommandation : les garder, ils couvrent 80 % des cas en une ligne.
5. Premier run (état absent) : sémantique explicite et documentée (valeur par défaut configurable, ou omission conditionnelle du fragment). Un `{{ state.lastTimestamp }}` qui rend une chaîne vide dans un filtre OData produit une requête invalide — ce cas doit être traitable dans le YAML.

## Critères d'acceptation

- `AC1` — `httpPolling` avec `endpoint: .../orders?$filter=LastModifiedDate gt {{ state.lastTimestamp }}` émet la valeur d'état, correctement encodée (cf. Story 25.1).
- `AC2` — Idem dans un header.
- `AC3` — Idem dans le `body` d'un `httpPolling` en POST.
- `AC4` — Idem dans une valeur de `queryParams`.
- `AC5` — `state.lastId` (ou nom canonique retenu) disponible dans les mêmes emplacements.
- `AC6` — Les 3 inputs exposent les **mêmes** noms de variables ; un tableau de correspondance ancien → nouveau nom figure dans la story de release.
- `AC7` — Premier run sans état : comportement testé pour chaque emplacement, avec le mécanisme de valeur par défaut.
- `AC8` — L'état écrit après exécution reste inchangé (aucune régression sur `internal/runtime/pipeline.go:setupStatePersistence` et le partage du `StateStore`).
- `AC9` — Un exemple sous `examples/` démontre un polling incrémental via filtre OData, validé par `./cannectors validate --verbose`.
- `AC10` — `go test ./...` et `golangci-lint run ./...` passent.
