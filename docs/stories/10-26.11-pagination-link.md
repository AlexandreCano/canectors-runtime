# Story 26.11 — Pagination de type `link` (`nextUrlField` et/ou `nextUrlHeader`)

**Epic** : 26 — Fonctionnalités identifiées par les migrations de connecteurs
**Type** : Feature
**Priorité** : Haute (mode de pagination très répandu, aujourd'hui infaisable)
**Ordre d'implémentation** : **10 / 17** — phase C — Incrémental
**Prérequis** : Story 25.1, Story 26.9

## Contexte

`$defs/pagination` (`internal/config/schema/common-schema.json:381-396`) impose `type` **et** `param`, avec `type` restreint à `cursor | offset | page`. Le modèle est donc : *cannectors construit l'URL de la page suivante à partir d'un paramètre*.

Beaucoup d'API ne fonctionnent pas ainsi : elles renvoient **l'URL complète** de la page suivante, et le client n'a qu'à la suivre :

- dans le corps : `{"next": "https://api…/orders?cursor=abc123"}`, `nextRecordsUrl` (Salesforce), `@odata.nextLink` (OData), `links.next` (JSON:API)
- dans un en-tête : `Link: <https://api…/page/2>; rel="next"` (RFC 8288 — GitHub, GitLab et beaucoup d'autres)

Aujourd'hui c'est irréalisable : `param` est requis, et il n'existe aucun moyen de dire « la page suivante est cette URL ». Les migrations concernées se sont arrêtées là.

## Comportement attendu

1. Nouveau `type: link`, avec `param` **non requis** dans ce cas (assouplir le `required` du schéma par un bloc `if`/`then` conditionné au type).
2. Deux sources possibles, combinables :
   - `nextUrlField` — chemin en notation pointée dans le corps de la réponse (supportant `@odata.nextLink` et autres clés à caractères spéciaux)
   - `nextUrlHeader` — nom d'en-tête. Pour `Link`, parser selon **RFC 8288** et sélectionner `rel="next"` — via une bibliothèque maintenue, pas un `strings.Split` maison (cf. `cannectors/CLAUDE.md`, réflexe « check library first »).
3. Précédence explicite si les deux sont configurés (recommandation : champ du corps d'abord, en-tête en repli — à documenter).
4. Fin de pagination : champ/en-tête absent, vide, ou `null` ⇒ arrêt propre.
5. **Sécurité — point critique** : l'URL suivante vient de la réponse d'un serveur. Elle doit être validée avant d'être suivie :
   - schéma autorisé (https, et http seulement si explicitement permis)
   - contrainte d'hôte : par défaut, même hôte que l'endpoint initial ; élargissement possible par une allowlist explicite. Sans cela, une API compromise redirige le connecteur — avec ses credentials — vers un hôte arbitraire (SSRF).
6. URL relative acceptée et résolue contre l'URL de la requête courante (`url.URL.ResolveReference`).
7. Garde anti-boucle : limite de pages (réutiliser la borne existante si `pagination` en a déjà une), et détection d'une URL suivante identique à l'URL courante.
8. L'authentification et les en-têtes configurés sont réappliqués sur la page suivante ; les `queryParams` statiques ne doivent **pas** être re-fusionnés dans une URL déjà complète (interaction avec la Story 25.1 — à tester explicitement).

## Critères d'acceptation

- `AC1` — `type: link` + `nextUrlField: next` suit 3 pages et agrège les records.
- `AC2` — `nextUrlField: "@odata.nextLink"` fonctionne (clé à caractères spéciaux).
- `AC3` — `nextUrlHeader: Link` avec `<…>; rel="next", <…>; rel="prev"` suit uniquement `next`.
- `AC4` — En-tête `Link` sans `rel="next"` ⇒ fin de pagination.
- `AC5` — Champ absent / vide / `null` ⇒ fin de pagination sans erreur.
- `AC6` — URL relative résolue correctement contre l'URL courante.
- `AC7` — URL suivante sur un hôte différent : refusée par défaut avec une erreur explicite ; acceptée si l'hôte figure dans l'allowlist.
- `AC8` — URL suivante en `http` alors que l'initiale est en `https` : refusée par défaut.
- `AC9` — URL suivante identique à l'URL courante : détectée, arrêt avec erreur (pas de boucle infinie).
- `AC10` — Limite de pages respectée, avec un log explicite quand elle est atteinte (jamais de troncature silencieuse).
- `AC11` — L'authentification est réappliquée sur les pages suivantes (test avec un stub exigeant le header sur chaque page).
- `AC12` — `queryParams` statiques non dupliqués dans l'URL suivante.
- `AC13` — `type: link` sans `param` valide ; `type: cursor` sans `param` reste rejeté.
- `AC14` — L'état persistant reste correct sur une pagination multi-pages (interaction Story 26.9, AC8).
- `AC15` — Exemple sous `examples/` avec pagination par `Link` header, validé par `./cannectors validate --verbose`.
- `AC16` — `go test ./...` et `golangci-lint run ./...` passent.
