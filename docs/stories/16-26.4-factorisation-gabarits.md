# Story 26.4 — Factorisation des gabarits (fragments réutilisables)

**Epic** : 26 — Fonctionnalités identifiées par les migrations de connecteurs
**Type** : Feature
**Priorité** : Moyenne-haute (devient haute dès que le multi-tenant arrive)
**Ordre d'implémentation** : **16 / 17** — phase G — Échelle
**Prérequis** : aucun
**Débloque** : Story 26.2

## Contexte

`{% include %}` — ainsi que `extends`, `import`, `from` — est rejeté à la compilation du gabarit :

```go
// internal/template/rewrite.go:145
case "include", "extends", "import", "from":
    err = fmt.Errorf("{%% %s %%} is not supported: a template must be self-contained, "+
        "because the tags of a loaded template would bypass contextual escaping", keyword)
```

Le refus est **motivé et correct** : le moteur réécrit les gabarits pour injecter un échappement dépendant de la cible (`Target`, cf. aussi le rejet de `{% filter %}` pour les cibles qui échappent). Un fragment chargé dynamiquement n'aurait pas subi cette réécriture et contournerait l'échappement contextuel.

Mais la conséquence pratique est qu'**aucune factorisation n'est possible** : un en-tête SOAP, un bloc d'adresse, une enveloppe JSON commune doivent être recopiés dans chaque gabarit de chaque pipeline. Avec du multi-tenant (Story 26.2) c'est intenable.

## Comportement attendu

Permettre la réutilisation **sans casser la garantie d'échappement contextuel**. Axes possibles, à évaluer :

- **(A) Inclusion résolue à la compilation, avec propagation du `Target`.** Les fragments sont résolus avant la réécriture, puis l'ensemble est réécrit d'un bloc avec la cible du gabarit hôte. La garantie d'échappement est préservée parce que le fragment traverse exactement le même pipeline de réécriture que le corps hôte. C'est la piste la plus prometteuse : c'est un `include` statique, pas un chargement dynamique.
- **(B) Fragments déclarés dans le pipeline YAML** (bibliothèque de snippets nommés), inlinés à la compilation. Même mécanisme, surface de configuration différente.
- **(C) Macros** (`{% macro %}` / `{% call %}`) définies dans le même fichier — factorisation intra-fichier seulement, gain partiel.

Recommandation : **(A)**, avec un chemin de fragment **statique** (littéral, non calculé depuis un record) — c'est cette contrainte qui rend la garantie tenable. Un chemin dynamique reste rejeté, avec le message d'erreur actuel.

## Contraintes non négociables

1. L'échappement contextuel reste intégralement appliqué au contenu inclus, avec la cible du gabarit hôte.
2. Aucune inclusion dont le chemin dépend de données d'exécution.
3. Détection des cycles d'inclusion, avec erreur claire.
4. Résolution des chemins **relative au fichier de pipeline**, sans échappement hors d'une racine autorisée (pas de `../../etc/passwd`).
5. Les erreurs de compilation d'un fragment nomment le fichier fragment **et** le gabarit hôte.

## Critères d'acceptation

- `AC1` — Un fragment inclus par deux gabarits distincts produit un rendu identique à la version copiée-collée.
- `AC2` — Le contenu inclus est échappé selon la cible de l'hôte : test avec un même fragment rendu vers une cible qui échappe (ex. XML/SOAP) et une qui n'échappe pas ; le résultat diffère correctement.
- `AC3` — Un chemin d'inclusion dynamique est rejeté à la compilation avec un message explicite.
- `AC4` — Un cycle A→B→A est détecté et rejeté.
- `AC5` — Un chemin sortant de la racine autorisée est rejeté.
- `AC6` — Inclusion imbriquée sur 3 niveaux fonctionne.
- `AC7` — Une erreur de syntaxe dans un fragment produit un message citant le fichier fragment et le gabarit hôte.
- `AC8` — `{% extends %}`, `{% import %}`, `{% from %}` restent rejetés (ou leur support est décidé explicitement et testé — pas d'autorisation implicite par effet de bord).
- `AC9` — `validate` détecte un fragment manquant sans exécuter le pipeline.
- `AC10` — Un exemple sous `examples/` avec un fragment SOAP partagé, validé par `./cannectors validate --verbose`.
- `AC11` — `go test ./internal/template/...` puis `go test ./...` et `golangci-lint run ./...` passent.
