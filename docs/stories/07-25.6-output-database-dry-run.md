# Story 25.6 — L'output `database` en `--dry-run` : aucun aperçu et connexion ouverte quand même

**Epic** : 25 — Bugs remontés par les migrations de connecteurs
**Type** : Bug
**Priorité** : Moyenne-haute (le dry-run est le principal outil de confiance avant une bascule)
**Ordre d'implémentation** : **07 / 17** — phase B — Contrats
**Prérequis** : aucun

## Contexte

`executeDryRunPreview` (`internal/runtime/pipeline.go:303-311`) fait une assertion de type sur `output.PreviewableModule` et sort silencieusement (log `Debug`) si le module ne l'implémente pas :

```go
previewable, ok := e.outputModule.(output.PreviewableModule)
if !ok {
    logger.Debug("output module does not implement PreviewableModule, skipping preview", ...)
```

Les implémentations existantes sont `StubModule` (`internal/modules/output/stub.go:70`), `HTTPRequestModule` et `SOAPRequestModule` (`internal/modules/output/soap_request.go:364`). **`internal/modules/output/database.go` n'implémente pas l'interface.**

Deux conséquences :

1. `cannectors run --dry-run` sur un pipeline à output `database` n'affiche **rien** — l'utilisateur ne peut pas vérifier le SQL qui serait exécuté, exactement là où il en a le plus besoin (un `INSERT`/`UPDATE` est irréversible).
2. Le module **ouvre malgré tout la connexion** à la base en dry-run. Un dry-run doit être sans effet de bord observable : ni connexion, ni pool, ni transaction. Sur une base de production dont on n'a pas les droits, le dry-run échoue alors qu'il n'aurait jamais dû toucher au réseau.

Note de conception : `internal/modules/output/output.go:170` affirme que « seul `PreviewableModule` est HTTP-specific ». Or `connector.RequestPreview` est un type de preview orienté requête HTTP (`pkg/connector/types.go:136`). L'interface d'aperçu doit pouvoir décrire une opération SQL sans se déguiser en requête HTTP.

## Comportement attendu

1. `--dry-run` sur un output `database` affiche, par record ou par lot : l'opération (`INSERT`/`UPDATE`/`UPSERT`/requête custom), la table cible, le SQL paramétré, et les valeurs de paramètres — **avec masquage des valeurs sensibles** cohérent avec `SanitizeURL` côté HTTP.
2. Aucune connexion n'est ouverte en dry-run : ni au démarrage du module, ni à l'aperçu. **Décision actée** : le constructeur résout la DSN, détecte le driver et compile le SQL sans dialer (`database.Resolve` / `database.OpenResolved`), et une interface optionnelle `output.ConnectableModule` est appelée par l'executor **avant le stage input** hors dry-run. Une base injoignable échoue donc toujours avant que la source ne soit interrogée et qu'un enrichissement ne soit facturé.
3. Le format d'aperçu est généralisé pour ne plus supposer HTTP. **Décision actée** : type commun `connector.OperationPreview{Kind, RecordCount, HTTP *HTTPPreview, SQL *SQLPreview}`, exactement un bloc rempli selon `Kind`. Le doublon `output.RequestPreview` est supprimé au profit du type de `pkg/connector` — la conversion manuelle de `pipeline.go` disparaît avec lui. `PreviewRequest` devient `PreviewOperations`.
4. Un output qui ne sait pas se prévisualiser doit le dire à l'utilisateur (message explicite au niveau `Info`/`Warn`), pas seulement en `Debug`. Un dry-run vide ne doit jamais être confondu avec « rien ne se passerait ».

## Critères d'acceptation

- `AC1` — `cannectors run --dry-run` sur un pipeline `→ database` affiche le SQL et les paramètres de chaque opération.
- `AC2` — Le dry-run n'ouvre aucune connexion : test avec une DSN pointant vers un hôte inexistant → dry-run réussit et affiche l'aperçu.
- `AC3` — `--verbose` enrichit l'aperçu (valeurs complètes des paramètres) comme pour l'output HTTP.
- `AC4` — Les valeurs sensibles (credentials dans la DSN, colonnes marquées sensibles s'il en existe) sont masquées par défaut. *Note d'implémentation* : il n'existe aucun marquage de colonne sensible dans cannectors — le masquage porte donc sur la DSN (`database.SanitizeConnectionString`, dévoilée par `dryRunOptions.showCredentials`). Les valeurs liées sont des données de record, tronquées pour la largeur hors `--verbose`.
- `AC5` — Le mode batch de l'output database est prévisualisé de façon lisible (N lignes agrégées, pas N pages de log).
- `AC6` — Un output non prévisualisable produit un message explicite en sortie CLI.
- `AC7` — `var _ PreviewableModule = (*DatabaseOutput)(nil)` (ou équivalent) présent, comme pour les autres modules.
- `AC8` — `go test ./...` (contrat d'interface partagé ⇒ portée large) et `golangci-lint run ./...` passent.
